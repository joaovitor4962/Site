Shift-left security: SAST, DAST, SCA e container scanning no pipeline

Como integramos segurança no CI/CD sem travar velocidade: gate quality, auto-remediation, policy-as-code, métricas de risk score por release.

10 min de leitura27/09/2026IT Cloud Solutions

O Problema: Segurança no Final = Atraso e Custo

Pentest só em produção? Custo de correção 10-100x maior. Shift-left = mover segurança para a esquerda no pipeline: commit → build → test → deploy. Cada stage tem gate automatizado.

Os 4 Pilares no Pipeline

SAST (Static Application Security Testing)

Análise de código fonte/bytecode sem executar. Detecta: SQLi, XSS, path traversal, hardcoded secrets, crypto fraca. Ferramentas: SonarQube, Semgrep, CodeQL, Checkmarx, Fortify. Gate: falha no build se critical/high.

DAST (Dynamic Application Security Testing)

Testa app rodando (black-box). Detecta: auth bypass, IDOR, SSRF, misconfig headers. Ferramentas: OWASP ZAP, Burp Suite Enterprise, Nuclei. Gate: roda em staging, falha se high/critical.

SCA (Software Composition Analysis)

Varre dependências (npm, maven, gradle, pip, go mod, cargo). CVE, licença, versão desatualizada, malicious package. Ferramentas: Dependabot, Renovate, Snyk, OWASP Dependency Check, Trivy. Gate: bloqueia CVE > 7.0 (CVSS) sem exceção aprovada.

Container Scanning

Imagem Docker → base image, OS packages, app deps, config (root user, secrets, exposed ports). Ferramentas: Trivy, Grype, Syft, Docker Scout, Aqua Trivy. Gate: assinatura (cosign/sigstore) + policy OPA (ex: no critical, base image approved).

Pipeline de Referência (GitHub Actions / GitLab CI)

stages:
  - sast          # SonarQube / Semgrep / CodeQL
  - sca           # Trivy fs / Dependency Check
  - build         # Docker build
  - container-scan # Trivy image / Grype / Syft
  - sign          # cosign sign --key env://COSIGN_PRIVATE_KEY
  - dast          # ZAP / Nuclei (staging deploy)
  - policy-gate   # OPA/Conftest (rego policies)
  - deploy        # ArgoCD / Helm (se all gates pass)

Policy-as-Code (OPA/Rego) — Exemplos

# Block critical CVEs in container
deny[msg] {
  input.vulnerabilities[_].severity == "CRITICAL"
  msg := "Critical CVE found: " + input.vulnerabilities[_].id
}

# Require signed images
deny[msg] {
  not input.signatures[_]
  msg := "Image must be signed (cosign/sigstore)"
}

# No root user in container
deny[msg] {
  input.config.User == "root"
  msg := "Container runs as root"
}
