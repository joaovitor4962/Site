GitOps com ArgoCD: promovendo apps entre ambientes com segurança e auditoria

App of Apps, ApplicationSets, RBAC, sigstore, policy validation (OPA), rollback automático, drift detection. Padrão enterprise que usamos.

12 min de leitura22/10/2026IT Cloud Solutions

Por que GitOps?

Git = única fonte de verdade. Cluster state declarado em repositório (Helm/Kustomize). ArgoCD sincroniza continuamente. Mudança = PR → review → merge → deploy automático. Auditoria nativa (quem, quando, o que), rollback = git revert.

Componentes-Chave

App of Apps (Root Application)

Um Application ArgoCD que aponta para a pasta root-apps/ e cria recursivamente todos os Applications filhos. Bootstraps todo o fleet com um único recurso.

ApplicationSets (Dynamic Apps)

Gera Applications dinamicamente baseados em: cluster labels (env=prod), PR generators (preview envs), matrix (app x cluster). Elimina copy-paste.

RBAC + Projects

Project por time/tenant: source repos permitidos, destination clusters/namespaces, resource kinds. SSO via Dex/OIDC (Azure AD, GitHub, GitLab).

Policy Validation (OPA Gatekeeper)

ConstraintTemplates: no privileged containers, required labels, resource limits, approved images only, no hostPath. Validado no admission controller ANTES do ArgoCD aplicar.

Sigstore / Cosign (Supply Chain)

Assinatura de imagens (cosign sign), verificação no ArgoCD (ImageVerifier), keyless (OIDC), transparency log (Rekor). Garante: imagem = o que foi buildado no CI.

Drift Detection & Auto-Remediation

ArgoCD compara desired (Git) vs actual (cluster) a cada 3min. Drift → alerta Slack/PagerDuty. Auto-heal: argocd app sync --prune --self-heal (opcional, com aprovação).

Promoção Dev → Staging → Prod

StageTriggerAprovaçãoValidações
DevPush to main (app repo)Auto (sem aprovação)Unit test, SAST, SCA, container scan, OPA policy
StagingTag staging-v* ou PR mergeAuto + smoke testIntegration test, DAST, performance baseline
ProdTag v* (release)Manual (Approver role)Canary (Argo Rollouts), 10% → 50% → 100%, rollback auto se error rate > 1%

Rollback em Segundos

# Via CLI (qualquer um com permissão)
argocd app rollback minha-app 3   # revisão 3 (Git commit)

# Via UI: Apps → minha-app → History → Rollback
# Auditoria: quem fez, quando, qual revisão, diff
Dica: Use Argo Rollouts (CRD) para canary/blue-green progressivo no ArgoCD. Integra com Istio/ALB/NGINX para traffic shifting. Rollback automático baseado em métricas Prometheus (error rate, latency, business KPIs).
