Módulos Terraform reutilizáveis: versionamento, testagem e registry privado

Estrutura de repositório, semantic versioning, terratest, checkov, infracost, renovate. Como entregamos infra como produto interno.

10 min de leitura15/10/2026IT Cloud Solutions

O Problema: Copy-Paste de Terraform

Times copiam pastas, alteram nomes, criam drift, não testam, não sabem custo, não têm owner. Módulo = produto: versão, changelog, testes, documentação, owner, SLA.

Registry Privado (Terraform Cloud / Enterprise / Artifactory / S3)

  • Terraform Cloud/Enterprise: Private registry nativo, versioning, search, dependency resolution, policy enforcement (Sentinel/OPA)
  • Artifactory / Nexus: Generic repo, suporte a provedores + módulos, promoção dev→prod
  • S3 + DynamoDB (backend): Baixo custo, versioning via S3 object versioning, index via metadata

Consumo pelos Times (Self-Service via ServiceNow)

# Catalog item ServiceNow → aprovação → gera PR no repo do time
module "vnet" {
  source  = "registry.itcloudsolutions.com.br/azure/vnet"
  version = "~> 1.2"   # patch auto, minor manual

  resource_group_name = "rg-prod-sp"
  location            = "Brazil South"
  address_space       = ["10.100.0.0/16"]
  subnets = {
    app = { cidr = "10.100.1.0/24", nsg = "nsg-app" }
    db  = { cidr = "10.100.2.0/24", nsg = "nsg-db" }
  }
  tags = var.common_tags
}
Dica: Semantic versioning rigoroso: patch = bugfix/backwards compatible, minor = feature/backwards compatible, major = breaking change. ~> 1.2 permite patches, bloqueia minor. Renovate abre PRs automáticos para minor/major com notas de breaking change.
