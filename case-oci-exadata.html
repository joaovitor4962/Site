Case Study

Migração Oracle Exadata on-prem para OCI Exadata Cloud@Customer

Setor financeiro, 15 TB, janela zero downtime. BYOL, autonomia de dados, patching automatizado, latência <1ms para aplicações legadas.

OCIExadataDatabaseBanco

O Desafio

Banco médio com Exadata on-prem (X8M) chegando ao fim de vida do hardware. Necessidade de modernizar sem reescrever aplicações legadas (PL/SQL, Forms, Reports), manter soberania de dados (regulação BACEN), latência determinística para core banking e reduzir TCO.

Restrições Críticas

  • Janela zero downtime: Core banking 24/7, manutenção apenas domingo 02-04h
  • Soberania de dados: Dados não podem sair do Brasil (BACEN, LGPD)
  • Latência < 1ms: Aplicações legadas sensíveis a round-trip
  • Licenciamento BYOL: Manter investimento em licenças Oracle existentes
  • Patching controlado: Janelas rigorosas, validação em homologação

A Solução: OCI Exadata Cloud@Customer

Levamos a nuvem Oracle para o data center do cliente — hardware Exadata gerenciado pela Oracle, controle de dados do cliente, faturamento cloud.

Arquitetura Implementada

  • 2 Exadata X9M Cloud@Customer (HA ativo-ativo, sites primário/DR)
  • VM Cluster dedicado por ambiente (PROD, HOMOL, DEV)
  • Autonomous Database para novas cargas analíticas
  • Data Guard Far Sync para DR síncrono (RPO=0)
  • OCI Console + API para gestão, patching, scaling

Estratégia de Migração Zero Downtime

  • ZDLRA (Zero Data Loss Recovery Appliance) para backup contínuo
  • GoldenGate 21c: replicação lógica bidirecional on-prem → Cloud@Customer
  • Switchover planejado: 45 min janela, rollback testado em HOMOL
  • Validação: checksum tables, contagem linhas, performance benchmarks
  • Cutover domingo 02h: DNS flip, conexão apps → novo listener SCAN

Otimização de Licenciamento & Custo

  • BYOL: licenças EE + RAC + Diagnostic/Tuning Pack reaproveitadas
  • Universal Credits: pagamento por consumo OCPU/hora
  • Autoscaling OCPU: escala automática em picos (batch noturno, fechamento)
  • TCO 40% menor vs refresh on-prem (CAPEX + OPEX 5 anos)

Performance & Operação

  • Latência média 0.4ms (vs 0.8ms on-prem) — Smart Scan offload
  • Patching Oracle gerenciado: rolling, zero downtime, agendado pelo cliente
  • Monitoring: OCI Monitoring + Enterprise Manager Cloud Control
  • Backup: ZDLRA + Object Storage imutável, retenção 10 anos

Resultados Mensuráveis

0downtime migração
40%TCO menor 5 anos
2xperformance queries
100%soberania dados
Depoimento do DBA Sênior: "O Cloud@Customer resolveu o paradoxo: nuvem gerenciada pela Oracle, dados no nosso data center, latência de on-prem, custo de cloud. A migração via GoldenGate foi transparente para as aplicações."
