Catálogo de dados, lineage e quality: implementando DataHub + Great Expectations

Metadados ativos, ownership, PII detection, testes de qualidade no pipeline, alertas de freshness. Como escalar governança sem burocracia.

9 min de leitura29/09/2026IT Cloud Solutions

Por que Governança Falha

Planilhas de dicionário de dados desatualizadas, ownership vago ("é do time de dados"), lineage manual, quality reativa (descobre no dashboard). Governança eficaz é automatizada, embutida no pipeline, com dono claro.

Stack: DataHub (Catálogo + Lineage) + Great Expectations (Quality)

DataHub (Acryl / LinkedIn)

Catálogo unificado, lineage coluna-a-coluna (SQL parser + dbt + Airflow), ownership (Slack, email, team), tags/glossário, PII detection (regex + ML), search & discovery, GraphQL/REST API, ingestion via CLI/Airflow/Kafka.

Great Expectations (GX)

Expectativas declarativas (Python/YAML): uniqueness, completeness, validity, distribution, custom. Validation em runtime (Airflow/dbt/CI), Data Docs (HTML), Checkpoints, Profiler, integração DataHub (emite resultados como metadata).

Implementação Passo a Passo

  1. Deploy DataHub: Docker Compose (dev) / Kubernetes (prod) — MySQL + Elasticsearch + Kafka + MAE (Metadata Audit Event)
  2. Ingestion Recipes: Snowflake/BigQuery/Redshift (profiling on), dbt (manifest.json + catalog.json), Airflow (OpenLineage), Power BI/Looker (API), Kafka (schema registry)
  3. Ownership Mapping: Glossary terms → Domain → Owner (team + Slack channel). Auto-assign via regex no schema/table name
  4. PII Detection: Regex patterns (CPF, CNPJ, email, cartão, telefone) + ML classifier (Presidio) → tag `PII:true` + alerta no Slack
  5. Great Expectations Suite: Por domínio (vendas, financeiro, cliente). Expectativas: `expect_column_values_to_not_be_null`, `expect_column_values_to_be_unique`, `expect_column_values_to_be_between`, `expect_table_row_count_to_be_between`, `expect_column_kl_divergence_to_be_less_than` (drift)
  6. Checkpoints no Pipeline: dbt `on-run-end` → GX validation → se falha: block deploy + alerta PagerDuty/Slack
  7. Data Docs + DataHub Sync: Resultados do GX → DataHub (aspect `DataQuality`, `Profile`, `Freshness`)
  8. Alertas de Freshness: SLA por dataset (ex: `fct_vendas` fresh < 2h). DataHub + Monte Carlo / Elementary monitora + alerta
